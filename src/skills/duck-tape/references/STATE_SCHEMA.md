# Session State Schema (Tier 2)

## File

Path: `.duck-tape/<session_id>.state.md`
Session ID: `<YYYY-MM-DD-HHMM>` (timestamp-based, generated by duck-tape)

## Agent State Schema

```
# Agent State

Session: `<session-id>` | Cwd: `<absolute-path>` | Repo/Branch: `<repo>@<branch>`
Created: `<ISO-8601>` | Updated: `<ISO-8601>` | Compactions: 0

## Approved Workflow
<what was approved in user's terms. Link spec/plan/ticket if one grounds this work>

## Position
- **Current:** <one step in flight>
- **Done:** <ordered newest last>
- **Remaining:** <in order>

## Decision Log
<ISO-8601> APPROVED/REJECTED: <what> - <reasoning>
<one entry per decision, append new>

## Established Facts
<facts established during session>

## Re-derivation
<how to recover state not written above: which commands to run, which files to read, which endpoint to query. Assume reader has lost all conversation history>

## Suggested Skills
<optional. Skills next session should invoke. Consumed by next agent, does not translate to CONTEXT.md>
```

## Section Definitions

### Header

Metadata block. Fields:
- `Session`: session ID (`<YYYY-MM-DD-HHMM>`)
- `Cwd`: absolute path of working directory
- `Repo/Branch`: `<repo>@<branch>` from git
- `Created`: ISO-8601 timestamp of first write
- `Updated`: ISO-8601 timestamp of last write
- `Compactions`: integer, incremented each time state file is rewritten (e.g. auto-compact re-writes)

### Approved Workflow

What was approved in the user's terms. Link spec/plan/ticket if one grounds this work.

Translation: one key per approved workflow -> CONTEXT.md **Decisions**. Verbatim text.

### Position

Current state of work.
- `Current`: one step in flight.
- `Done`: ordered newest last.
- `Remaining`: in order.

Translation:
- `Current` -> CONTEXT.md **Session-Log** first entry: `Status: <current>` (if meaningful change).
- `Done` -> CONTEXT.md **Session-Log** entries appended after Status.
- `Remaining` -> CONTEXT.md **Open-Questions**, one question per item.

### Decision Log

Append-only. One entry per decision.

Format: `<ISO-8601> APPROVED/REJECTED: <what> - <reasoning>`

Translation: one key per decision -> CONTEXT.md **Decisions**. Status (APPROVED/REJECTED) preserved in entry text.

### Established Facts

Facts established during session.

Translation: one term per fact -> CONTEXT.md **Glossary**. Verbatim.

### Re-derivation

Recovery instructions for lost conversation history. Commands to run, files to read, endpoints to query. Assume reader has lost all conversation history.

Translation: verbatim copy -> CONTEXT.md **Notes** under `### Re-derivation <id>` subsection. No interpretation, no rewrite.

### Suggested Skills

Optional. Skills next session should invoke.

Translation: none. Consumed by next agent directly from state file. Does not land in CONTEXT.md.

## Translation Map (Rigid)

| State section | CONTEXT.md target | Rule |
|---|---|---|
| Approved Workflow | Decisions | one key per approved workflow, verbatim text |
| Position.Current | Session-Log | first entry: `Status: <current>` if meaningful change |
| Position.Done | Session-Log | entries appended after Status |
| Position.Remaining | Open-Questions | one question per remaining item |
| Decision Log | Decisions | one key per decision, status preserved in text |
| Established Facts | Glossary | one term per fact, verbatim |
| Re-derivation | Notes | verbatim copy under `### Re-derivation <id>` |
| Suggested Skills | (none) | consumed by next agent, not translated |

No interpretation. Each state section maps to exactly one CONTEXT.md target. Deterministic.

## Lifecycle

### Write

Single write on `/duck-tape` invocation. No mid-session checkpoints.

### Rotation

- Max 10 state files in `.duck-tape/`.
- On write, if count exceeds 10: drop oldest file by session ID (lexicographic = chronological).
- Note dropped ID in CONTEXT.md Session-Log: "Rotated out session state: <id>".

### gitignore

- Auto-create `.duck-tape/.gitignore` with content `*` on first write if missing.
- Self-contained. Does not touch root `.gitignore`.
- State files not meant for commit.

## Redaction

Applies to all state content before write. Same rules as CONTEXT.md redaction:

- Scan for secrets/PII: API keys, passwords, tokens, connection strings, env var values, personally identifiable information.
- On detection: reject flagged content. Report findings. Ask user to redact source or confirm mask-in-place (`<REDACTED>`).
- Never write raw secrets to state files. Masked content only after user confirmation.
- Redaction applies to all sections including Re-derivation and Suggested Skills.

## Boundaries

- State file uses Agent State schema only. No CONTEXT.md sections in state file.
- Translation is rigid. No interpretation of content to pick target section.
- Re-derivation is verbatim. Never rewrite or summarize.
- Suggested Skills does not translate. Next agent reads state file directly.
- State files are working memory, not persistent. Rotation cap enforced.
