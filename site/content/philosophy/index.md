# Philosophy

Rubber Duck exists to help developers think clearly, decide deliberately, and change code safely.

Three principles govern every skill:

- **[Duck Ladder](./duck-ladder.md)** — climb no further than needed. Prefer no change, then reuse, then stdlib, then existing deps, then smallest safe diff. Add new abstractions last.
- **[Evidence-first](./evidence-first.md)** — anchor claims in artifacts (code, diff, logs, tests, config). If evidence is missing, state assumptions and ask.
- **[Decision ownership](./decision-ownership.md)** — the developer owns product, architecture, implementation, and acceptance decisions. Skills present options; they never decide silently.

These aren't style preferences. They're safety mechanisms. Skills that violate them stop being helpful and start being dangerous.

For the full policy text (checkpoints, phase caps, safety carve-outs), see [Safety Gates](../architecture/safety-gates.md).
